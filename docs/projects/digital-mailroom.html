Case study

Digital-Mailroom

DSHB capstone project · American Family Insurance (industry partner)

At a glance

10 Python packages: entity extraction, classification, routing, scalable workflows

1 LangGraph pipeline joining routing, experiments, scoring, data and deployment

Public data only the dataset was built from public sources; no partner data is involved

Dec 2026 expected completion; results are not public yet

The problem

A mailroom takes in a stream of documents: contracts, merger agreements, corporate records, letters and emails, insurance claims. Someone, or something, has to read each one, decide what it is, pull out the key facts and send it to the right place. An LLM can do that, but running one on every page is expensive, and the cost grows with volume.

The capstone with American Family Insurance asks how to cut the cost of AI inference while improving document processing. My part is the engineering behind that question: a pipeline that routes each document to the cheapest step that can handle it, and a way to measure whether the routing is any good.

Approach

The design is one LangGraph pipeline that joins legal-document routing, prompt experiments, deterministic scoring, dataset management and deployment in a single graph. The idea behind the cost goal is to send each document to the cheapest step that can handle it, and to reserve an LLM call for documents where that matters.

I split the work into ten packages so each part can be tested and swapped on its own.

What I built

  • Ten Python packages covering entity extraction, classification, routing and scalable workflows.
  • One LangGraph pipeline that joins legal-document routing, prompt experiments, deterministic scoring, dataset management and deployment.
  • Prompt experiments and deterministic scoring, so prompt choices are judged by fixed rules against known labels instead of by another model.
  • Dataset management for the public-source dataset described below.
  • A reproducible Docker environment so results can be rerun end to end.

The dataset

The capstone uses a dataset I assembled myself, called mailroom-dataset. It is built entirely from public datasets. None of the industry partner’s documents are in it, and none were used to build it.

The public sources fall into three groups.

  • Correspondence. The public Enron email corpus, deduplicated to unique texts, with labels from a mix of an LLM zero-shot pass, a join to a public email dataset, simple heuristics and manual review.
  • Contracts, merger agreements and corporate records. Documents from public SEC filings. These include exhibits from EDGAR, and public contract, merger-agreement and registration-statement collections whose clause labels I mapped onto document types and subclasses.
  • Insurance claims. Largely synthetic or rendered from structured public data. Some are rendered from the CMS DE-SynPUF public-use synthetic Medicare files into explanation-of-benefits style documents. Others come from public synthetic claim datasets for property, auto and claim-narrative cases.

The result has 3,302 documents across five types: contract, merger agreement, corporate record, correspondence and insurance claim. A fixed set of 323 documents is held out as the test split and kept out of training and validation. It is not an untouched set: the Mailroom-ML work also ran a routing-cutoff sweep and a decode-setting sweep on this same split (see the Mailroom-ML case study). Each type has subclasses, for example whether a piece of correspondence is a letter, an email, a memo or a notice.

Two safeguards matter here. Every source is pinned to an exact revision, so the dataset can be rebuilt byte for byte. And a leak audit checks that file names and titles do not give away the label; it caught exactly that problem in an earlier build, which I describe in the Mailroom-ML case study.

Results and links

Measured results from the capstone are not public while the project is running (expected completion December 2026), so I am not publishing numbers here. The classifier work that feeds it is public and fully reported:

  • Mailroom-ML: the ModernBERT classifier, its calibration and its routing gate, with a technical report.
  • Mailroom Reloaded: a related pipeline that uses that classifier as its first stage.
  • RVL-CDIP classifier study: a prompt-and-model study on a 16-class public document benchmark, with cost projections.

What I learned

  • A cost question is a measurement question. You cannot cut inference cost safely until you can say, with a held-out set, how often the cheap step is right.
  • Building your own dataset from public sources forces decisions that a ready-made benchmark hides: what counts as a label, what leaks it, and what must stay out of tuning.
  • Deterministic scoring keeps prompt experiments comparable, because the score does not depend on a model that can drift.
