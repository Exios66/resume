RVL-CDIP-Classifier

Vision LLMs & prompt engineering

At a glance

82.6% accuracy on 1,120 images (a larger slice, overlap with tuning not verified; 925 correct)

99.4% on the 160-image slice I tuned against, so an optimistic number

29 registered prompt versions, v0 to v19

≈ $0.0004 per image for the main model

The problem

RVL-CDIP is the standard benchmark for document-type classification: scanned pages from a tobacco-litigation archive, sorted into 16 classes such as invoice, memo, letter and budget. Models trained for it usually need labeled data and a fine-tuning pipeline. I wanted to know how far a general-purpose vision model could get with no training at all, using only the prompt, and what that would cost.

Approach

The model gets the page image and a long written prompt. The prompt names the 16 classes and then walks through an ordered list of checks, so that a page is judged by what it does rather than what it is about. I changed the prompt one version at a time and scored every version the same way, so each change could be traced to a number.

What I built

  • Preprocessing tools. A document processor converts TIFF and PDF pages to 300-DPI grayscale images and runs Tesseract OCR to get text with bounding boxes.
  • The classifier path. The evaluated classifier does not use that OCR output. It sends the vision model only a 1024×1024 grayscale image plus the prompt, through OpenRouter.
  • Versioned prompts. src/prompts.py holds every version, append-only, with a registry I can query by name.
  • Evaluation harness. Balanced, deduplicated slices of the dataset, exact-match scoring, per-class tables, confusion matrices, billed-cost tracking, and a Monte Carlo module that simulates voting and routing on top of the measured results.
  • Tests. 318 test functions across 21 test files.

Results

On the 160-image slice, accuracy climbed from 80.1% at v1 to 99.4% at v11.8. That is a tuning-slice number. I read the misses on that slice and wrote rules for them, so it overstates what the prompt can do on pages it has not seen.

The honest headline comes from larger slices. The same v11.8 prompt scored 82.6% on a balanced 1,120-image slice. That slice was built from the Hugging Face mirror of RVL-CDIP, with pixel-hash exclusion of the 800-image slice; I did not verify its overlap with the 160-image tuning slice. Across slice sizes it scored 87.2% at 320 images, 89.1% at 476 scored images, and 83.1% at 800. On that 800-image slice, the untuned v0 prompt scored 66.1%, so the prompt work is worth about 17 points on unseen pages.

Heads up. The 160-image points in both charts come from the slice I iterated on. The 1,120-image point is the one to quote. The 1,120-image slice excluded the 800-image slice by pixel hash, but I did not check it against the 160-image tuning slice or the other earlier slices, so it may share images with them. Treat it as a better estimate than the tuning slice, not as a clean test.

Where it fails is consistent. Budget (67.1%), letter (70.0%), presentation (70.0%) and scientific report (71.4%) are the weak classes on the 1,120 run, and the most common single error is letter predicted as memo (16 cases). In 72 of the misses, the correct class was the model’s own runner-up.

What I learned

  • Tuning accuracy is not accuracy. Fixing named misses one by one pushed the tuning slice to 99.4% while larger slices stayed in the low 80s. Later versions made this worse in places: a longer v16 prompt dropped to 96.2% on the tuning slice and scored 83.8% and 79.4% on two fresh slices.
  • Simulation needs a measurement behind it. The Monte Carlo model suggested sending the least-confident pages to a stronger model. When I ran that, accuracy went down slightly (96.2% to 94.3% on the tuning slice) at about 7.5 times the cost.
  • More resolution did not help. Full-size 2550×3300 images doubled prompt tokens and did not improve accuracy in an early comparison.
